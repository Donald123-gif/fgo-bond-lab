# 迦勒底 · 国服 / 日服牵绊研究室

纯静态 HTML / CSS / JavaScript，无构建依赖。国服数据为 2026-11-17 Atlas Academy CN 快照，包含 447 个可编队从者记录、2,508 张可检索礼装及 33 种非活动限定的牵绊礼装选项。

在页首选择国服或日服。编队、候选池和筛选按服务器保存，原国服存档继续使用。链接支持 `?region=CN` 和 `?region=JP`。日服使用 Atlas JP 的日文名称和效果，共有卡支持按国服名称搜索。运行 `python prepare_data.py --region JP` 可更新日服快照。两服使用相同的已建模牵绊规则。

## GitHub Pages 部署

仓库首次启用时，在 Settings → Pages → Build and deployment → Source 中选择 **GitHub Actions**。随后在 Actions 中运行 **Publish FGO Bond Lab**，或提交代码触发发布。

工作流先执行 `node test.cjs`，通过后将 `dist` 发布到 GitHub Pages。部署成功后，网页由 GitHub 托管，不需要自己的电脑开机。后续推送至 `main` 会自动验证并更新网站，正式地址见 Settings → Pages。

编队与筛选保存在当前浏览器的 localStorage 中，更换设备、浏览器或网站地址后不会自动同步。图片仍由 Atlas Academy 提供，游戏资料为随代码打包的国服快照。

## 本地运行

在本目录执行 `python -m http.server 5173 --directory dist`，打开 http://localhost:5173 。不要直接双击 index.html：计算使用 Web Worker，需要 HTTP 服务。

运行验证：`node test.cjs`。

## 使用

1. 设置御主等级或手动 Cost、基础牵绊、自有从者人数与前排人数。
2. 点击编队中的从者/礼装槽，在独立卡片弹窗中选择；从者选中后固定入队，可固定再临/灵衣。候选池用于管理持有从者，并可标记满绊。
3. 勾选拥有的候选礼装，设置满破或必带。每种按一张计算，候选数量按实际持有选择。默认选择是演示配置，不代表账号持有。
4. 点击计算。目标可切换全队最大或必选从者优先。预留战斗礼装槽及 Cost 可保留输出配置。

## 模型

穷举候选礼装子集，按从者身份分组进行 0/1 背包，状态为人数、前排人数、Cost。同一从者的形态互斥；先在相同费用和位置上保留足够的非劣候选，最终精确求解所选候选集。助战不计费用或个人收益，礼装效果按助战值计。礼装条件使用 Atlas 原始 trait ID 和 OR-of-AND 表达式。

支持普通关卡，以及一个自有冠位位的冠位钻研/认定战。仍不包含活动限定增益、特殊从者被动及战斗可行性。前排配置按开场前排建模。全局活动加成可手动录入；按个体区分的活动加成未建模。在从者候选池区分已达当前上限和已获得绊15被动。每名出击的自有绊15从者（包含后排）提供25%加成，助战不提供。日服开放绊16后可继续赚取自身牵绊。求解器枚举实际出击的被动数量，并按该数量计算每个成员的取整收益。旧存档的满绊标记仅表示自身收益为零，需手动确认已达绊15。[技能说明](https://news.fate-go.jp/2025/grand_saber/)英灵肖像各版本独立可选；每种礼装按一张，不限制同类纪念礼装的账号获取互斥，请按实际持有勾选。

国服数据中未收录的未来礼装不会加入，例如当前快照没有「迦勒底之人」，不能将混沌属性自行套用为已有20%加成。

## 数据更新

`python prepare_data.py` 从 Atlas CN 导出重新生成 `dist/data.js`。更新时同时核对日期、实装与模型适用性；本页不是自动联网同步。数据和素材来源见页面底部。角色素材版权归 TYPE-MOON / FGO PROJECT。


## 冠位与形态（v2）

- 选择冠位关卡后指定已戴冠的自有从者，求解时自动强制入队。钻研/认定战按选择的七骑士职阶或 EXTRA I/II 组过滤候选。
- 当前支持 1 个自有冠位位和 1 个冠位助战位。普通槽数量不变；自有冠位新增一个免费报酬槽和一个免费的自身十绊礼装专用槽。不会把后者错误当作第二个通用牵绊加成槽，不会增加御主 Cost 上限。
- 报酬槽可自动选优、锁定指定礼装或不使用。每种候选自有礼装按 1 张建模，普通槽与报酬槽不重复分配同一张。自动选择时对每个礼装集合把未绑定普通槽的礼装中费用最高的一张放入报酬槽；在本数据集所有选项均满足报酬槽条件、对收益影响与佩戴者无关的前提下，该分配精确最优。
- 冠位助战的普通槽、报酬槽分别设置并按助战倍率计收益。助战自身十绊礼装的战斗效果不参与本牵绊模型。
- 数据改用 CN nice_servant_lore 导出，按实际 ascensionAdd 映射战斗形象第1/2/3阶段和具名灵衣；不同阶段不再回退到不存在的“默认灵基”。相同特性阶段合并标注，每骑只能入队一次。结果显示具体形态、形态头像和礼装在其他形态的生效/失效列表；复制方案也带形态。
- 形态指开战采用的战斗形象，并非等级、卡面设置或宝具触发的战中变身。选择自动形态后应按结果手动设置，关闭随机再临；灵衣须已解锁。

冠位规则依据：[国服官方说明](https://line1-patch-fate.bilibiligame.net/manage/html/Notice/Game/ios/2026-05-15/activityNotice_9345_1778839560.html)。数据源：[Atlas CN 从者（含资料）](https://api.atlasacademy.io/export/CN/nice_servant_lore.json)。

## 选择界面（v3）

- 深蓝金边、从者和礼装卡面、职阶符号、稀有度与宝具色标；桌面和手机均使用独立网格弹窗。单选立即更新槽位，多选候选池点击确认后提交。原有本地配置自动迁移。
- 搜索匹配官方名称、图鉴编号和 `aliases`，忽略大小写与全半角。别名维护于 `aliases.json`，按图鉴编号关联，重新导入数据后保留。支持 C呆/术呆、宝石翁、黑杯；CN 官方名称「黑之圣杯」另有「黑色圣杯」搜索别名。
- 从者可按职阶、稀有度、宝具色和可用形态特性组合筛选；礼装可按稀有度、初始 NP、攻击、宝具、暴击、活动、牵绊等效果筛选。同一维度为或，不同维度为且。重置清空草稿，确认才应用，关闭取消。
- 礼装支持按 Cost、稀有度、图鉴及持有等级排序。持有等级由用户设置，默认 Lv.1，限制在礼装等级上限内；等级不改变牵绊加成倍率，满破状态单独设置。
- 普通槽支持全礼装目录。已建模牵绊礼装强制保留普通槽；其他礼装保留绑定并扣除槽位与 Cost。活动专属、特殊自身效果等未建模的收益不会凭空增加；战斗效果仅用于展示和筛选。
- 计算仍限定持有的候选牵绊礼装，每种自有礼装按一张。已绑定普通槽的礼装不能被移至免费冠位报酬槽。

`node test.cjs` 验证算法、冠位、真实灵基差异、别名、组合筛选和排序。浏览器验收覆盖弹窗开关、筛选草稿、选择返回、槽位与 Cost、候选取消、键盘和移动布局。

## 编队界面（v5）

戴冠战通过编队顶部开关启用。冠位从者直接在编队卡位选择，普通、报酬与自身牵绊槽纵向排列在该从者下方；冠位助战亦如此，不再使用独立模块。可将队内其他从者设为冠位。选中礼装以头像、等级、Cost 显示，名称保留在悬停提示与无障碍标签中。

## 队伍编成（v6）

- 主界面保持横向六槽，前 3 位为 Main，后 3 位为 Sub；手机左右滚动。助战也能换位，自有前排人数根据助战位置自动确定。
- 拖动顶部手柄（鼠标 / 触摸）交换整组成员与礼装；支持点击两处手柄、或键盘聚焦后按 Enter 交换，Esc 取消。位置顺序单独持久化，冠位额外槽跟随冠位从者。
- 计算直接回填主编队，移除独立结果卡片。手动选择的成员和普通礼装保留固定约束；自动补全标记为 AUTO，下次求解不会把自动结果误当成必选。
- 底部汇总当前 Cost、牵绊和各成员加成范围；换位时按实际前后排重新计算。Cost 超限以红色显示。具体灵基和条件加成差异仍在对应从者下方。
- 从者等级默认为 Lv.1，可手动填写实际等级，仅作显示，不影响 Cost 和当前牵绊模型。礼装显示持有等级和满破状态。
- 从者与礼装的筛选、排序分别保存于 localStorage 的 fgo-picker-preferences；礼装首次默认 levelDesc，确认筛选后保存，取消不会覆盖已保存配置。

浏览器验证：回填收益与求解器结果一致、手动礼装绑定、连续优化、鼠标拖拽高亮、触摸拖拽、助战跨排、冠位额外槽、少于 5 名自有从者、刷新恢复和移动端横向滚动。

## 拖拽与位置锁（v7）

- 可直接拖动从者卡面或卡片空白区交换整槽，手柄仍可使用。拖动普通礼装区域仅交换礼装；冠位额外专属槽随冠位从者移动。
- 从者和普通礼装各有独立锁图标，开启后保持内容与计算位置。锁定后排从者时，求解器限制其前后排状态，回填同时保持具体槽号；锁定礼装按槽位固定，允许优化该位置的未锁定从者。
- 显式手动换位仍可操作，锁标记随对应成员/礼装移动，以新位置作为下次优化的约束。解锁后恢复自动优化。助战本身不参与自有从者搜索，所在位置在计算中保留。
- 六槽次序不在回填时重建；普通礼装与助战礼装交换时同步满破状态和 Cost 口径，阻止自有礼装重复。
- 浏览器验证鼠标与原生触摸事件的两种拖拽、独立锁、前后排约束、连续计算、刷新恢复与解锁。算法新增 20 组受限穷举对照，并验证独立位置回填及无解场景。
